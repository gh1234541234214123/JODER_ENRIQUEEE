# JODER_ENRIQUEEE

Personal productivity + info-dump web app. Plain PHP (PDO) + MySQL/MariaDB with a
Bootstrap 5 UI. No framework, no build step.

- **v1 (done):** authentication, categories, tasks.
- **v2 (planned):** info dumps (`INFODUMPS`) and reactions (`reaccion`). The
  tables already exist in the schema; only the UI is missing.

## Features

- Email + password accounts (hashed with `password_hash`).
- Create, rename, complete/reopen and delete tasks.
- Filter tasks by status (all / pending / done) and by category.
- Create and delete categories; deleting one leaves its tasks uncategorized.
- Dashboard with live counts.
- Web installer: sets up the database and config on first run.
- Built-in favicon maker (letter + colour + shape), generated at install time.
- CSRF-protected forms, prepared statements, escaped output.
- Environment-aware config (local XAMPP vs production) and hardened `.htaccess`.

## Tech stack

| Layer    | Choice                                            |
|----------|---------------------------------------------------|
| Backend  | Plain PHP 7.4+ (PDO, prepared statements)         |
| Database | MySQL / MariaDB (InnoDB, foreign keys)            |
| Frontend | Server-rendered HTML + Bootstrap 5 (CDN)          |
| Server   | Apache (XAMPP locally, InfinityFree in production)|

## Requirements

- XAMPP (Apache + MySQL/MariaDB + PHP 7.4 or newer) for local development.
- A MySQL/MariaDB database (the installer can create it locally).

## Local setup (web installer)

1. Start **Apache** and **MySQL** from the XAMPP control panel.
2. Open <http://localhost/JODER_ENRIQUEEE/>. When `config/config.php` does not
   exist, the installer at `setup.php` opens automatically.
3. Fill in the details:
   - **Nombre del sitio**: the site name shown in the navbar and titles
     (default `JODER_ENRIQUEEE`).
   - Host: `localhost`
   - Base de datos: `joder`
   - Usuario: `root`
   - Contraseña: *(empty)*
   - Tick **Crear la base de datos si no existe**.
4. Click **Instalar**. The installer creates the database, applies `schema.sql`
   and writes `config/config.php`.
5. **Delete `setup.php`** from the server, then register an account.

### Manual alternative

Create the `joder` database in phpMyAdmin, import `schema.sql`, then copy
`config/config.example.php` to `config/config.php`. The local block already
matches the default XAMPP setup (`root`, no password).

## Configuration

`config/config.php` holds the credentials and is **gitignored**. It returns an
array with a `local` and a `production` block:

```php
return [
    'local'      => ['db' => ['host' => 'localhost', 'name' => 'joder',
                              'user' => 'root', 'pass' => ''],
                     'debug' => true,  'site_name' => 'JODER_ENRIQUEEE',
                     'session_driver' => 'database'],
    'production' => ['db' => ['host' => 'sqlXXX.infinityfree.com',
                              'name' => 'if0_XXXXXXXX_joder',
                              'user' => 'if0_XXXXXXXX',
                              'pass' => '...'],
                     'debug' => false, 'site_name' => 'JODER_ENRIQUEEE',
                     'session_driver' => 'database'],
];
```

`config/bootstrap.php` selects the block automatically: requests to
`localhost` / `127.0.0.1` use `local`, everything else uses `production`. The
installer writes the same credentials into both blocks.

The chosen `site_name` is exposed to the app as the `SITE_NAME` constant and
used in the navbar, page titles and footer. Edit it in `config/config.php` (or
re-run the installer) to change it later.

## How it works

### Accounts

- `register.php` validates the input, enforces a unique `Mote` and `email`, and
  stores `password_hash($password, PASSWORD_DEFAULT)`.
- `login.php` looks the user up by email and checks `password_verify`, then
  regenerates the session id. If **Mantener sesión iniciada** is ticked, a
  persistent login cookie is issued.
- `logout.php` clears the session, the persistent login token and both cookies
  (POST only).

### Sessions, cookies and "remember me"

Session handling lives in `includes/session.php` (wired up by
`config/bootstrap.php`):

- The session cookie is `HttpOnly`, `SameSite=Lax` and `Secure` on HTTPS.
- Storage is **database-backed** (`sesion` table) when
  `session_driver` = `database`; if the table is missing or the DB is
  unreachable it silently falls back to PHP's file sessions.
- **Idle timeout**: after `SESSION_IDLE` (2 h) without activity the session is
  emptied and the user is asked to log in again.
- **Remember me**: `includes/remember.php` issues a `remember` cookie holding
  `selector:validator`. Only a SHA-256 hash of the validator is stored in
  `remember_token`, and the token is rotated on every auto-login, so a stolen
  cookie is single-use.
- A dismissible **cookie consent banner** is shown until accepted (remembered in
  the `cookie_consent` cookie).

### Tasks (`tareas.php`)

Every action is a POST with a `csrf` field and an `action` value:

| Action   | Effect                                                        |
|----------|---------------------------------------------------------------|
| `create` | Adds a task (name + optional category). `completada` = 0.     |
| `toggle` | Flips `completada`.                                           |
| `update` | Renames a task and/or changes its category.                   |
| `delete` | Removes a task.                                               |

All queries are scoped to `ID_usuario = <session email>`, so users can only see
and modify their own data. Filters (`filtro`, `cat`) are read from the query
string.

### Categories (`categorias.php`)

- `create` adds a category owned by the current user.
- `delete` removes it; the `tarea.id_categoria` foreign key uses
  `ON DELETE SET NULL`, so its tasks survive as uncategorized.

## Favicon

Two ways to set the favicon:

1. **Generate** — the first letter of the site name drawn on a coloured shape
   (rounded / circle / square).
2. **Upload an image** — PNG, JPG, GIF, WEBP, SVG or ICO (max 2 MB).

The installer offers both (the upload wins if provided). You can change it
anytime from the **Favicon** page (`favicon.php`, requires login), which has a
live preview and the same two tabs.

- Generation writes `favicon.svg` (and `favicon.png` when GD is available).
- Uploads are stored as `favicon.<ext>`.
- Only one favicon format is kept at a time; switching clears the others.
- These files are generated/uploaded at runtime, gitignored and never shipped,
  so a re-deploy will not overwrite a custom favicon.
- `includes/header.php` links whichever favicon file exists.

## Database schema

Five tables (`schema.sql`):

- **Usuario** — users, keyed by `email`, unique `Mote`, hashed `password`.
- **categoria** — user-owned categories (`id_creador` → `Usuario.email`).
- **tarea** — tasks (`ID_usuario` → `Usuario.email`,
  `id_categoria` → `categoria.id` `ON DELETE SET NULL`).
- **INFODUMPS** — info-dump posts (`id_usuario` → `Usuario.email`); v2.
- **reaccion** — reactions (`id_dump` → `INFODUMPS.id`,
  `Id_usuario` → `Usuario.email`); v2.

## Security notes

- Credentials live only in `config/config.php`, which is **gitignored**.
- `config/` and `includes/` are blocked from web access via `.htaccess`.
- The root `.htaccess` blocks dotfiles and `*.sql`/`*.md`, disables directory
  listing and forces HTTPS in production.
- Passwords are hashed; sessions use `httponly`, `samesite=Lax` and `secure`
  (when on HTTPS) cookies.
- All SQL uses prepared statements; all output is escaped with
  `htmlspecialchars()`.
- All state-changing forms are POST + CSRF.
- Production hides PHP errors and logs them instead.

## Deploy to InfinityFree

1. In the InfinityFree control panel, create a MySQL database. Note the
   **host** (e.g. `sqlXXX.infinityfree.com`), **database name**, **user** and
   **password**.
2. Build the upload package:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy.ps1
   ```
   This creates `dist/joder-<timestamp>.zip` without any secrets
   (`config/config.php`, `deploy.ps1`, `PLAN.txt`, `migrations/` and `.git`
   are excluded).
3. Upload and extract the ZIP into `htdocs` (FileZilla or the online File
   Manager).
4. Visit the site over HTTPS. The installer opens automatically: enter the
   InfinityFree host, database name, user and password. **Do not** tick
   "create the database" (InfinityFree does not allow it), then click
   **Instalar**. The schema is applied and `config/config.php` is written.
5. **Delete `setup.php`** from the server.
6. Register an account.

### Updating an existing install

Apply the new files in `migrations/` (in order) through phpMyAdmin. Never drop
tables that hold data. Re-deploying the app files does not touch the database.

## Backups

Export the database regularly from phpMyAdmin. Keep dumps out of git
(`.gitignore` already ignores `*.sql` except `schema.sql`, `joder.sql` and
`migrations/*.sql`).

## Troubleshooting

- **Redirected to `setup.php` forever** — `config/config.php` is missing or the
  `config/` directory is not writable.
- **"Database connection error"** — check host/name/user/password in
  `config/config.php`; enable `debug` to see details.
- **500 error on the host** — some hosts reject certain `.htaccess` directives.
  Temporarily remove `Options -Indexes` and retry.
- **Locked out after deleting `config.php`** — the installer will run again;
  re-enter the same database details (existing data is preserved because the
  schema uses `CREATE TABLE IF NOT EXISTS`).
